# UI and application lifecycle reference

For tools, controls, dialogs, routing, saved designs, puzzle authoring, and verification. See [rendering](rendering.md) for Canvas drawing and [simulation](simulation.md) for world behavior and scene serialization.

Community integration, HTTP contracts, and local backend development are covered in [community backend](community-backend.md). Production configuration, Cloudflare operations, static hosting, and itch.io releases belong in [deployment](deployment.md).

## Ownership and entry points

* `src/main.ts` wires DOM events, active controllers, and the animation loop. `index.html` and `src/styles.css` define the framework-free shell and responsive layout.
* `src/game/navigation-controller.ts` owns screen transitions. `screen.ts` defines the complete tagged `AppScreen`; `app-route.ts` defines canonical paths and access checks.
* `saved-sandbox-controller.ts` and `saved-solution-controller.ts` own records and dirty sets; `saved-sandboxes.ts` and `puzzle-solutions.ts` own validated storage models.
* `workshop-session.ts` owns per-saved-ID sessions and editing locks. `workshop-surface-controller.ts` atomically mounts all session-bound world/view references and the nested-array path, cancelling gestures before rebinding.
* `puzzle-test-controller.ts` owns the tagged verification UI lifecycle; `puzzle-test-runner.ts` runs isolated cases. `src/ui/canvas-interaction-controller.ts` owns pointer capture and gesture state.
* `simulation-clock.ts` paces free-running sandbox ticks against wall-clock time and tracks each committed step's animation window; the puzzle test controller drives it through callbacks. `src/ui/dropup-menu.ts` owns the open state of the speed, export, and test-case menus, which the sandbox and puzzle test flows share.

Use these ownership boundaries rather than adding parallel session state to the entry point.

## Navigation and persistence invariants

Canonical internal routes are `/`, `/sandbox`, `/sandbox/:sandboxId`, `/puzzles/:puzzleId`, and `/puzzles/:puzzleId/solutions/:solutionId`. Browser URLs store them in the fragment, e.g. `index.html#/sandbox`; the hosting pathname and query string never change. In-app navigation pushes fragment URLs with the History API; `hashchange` handles direct fragment edits and browser Back/Forward through the same access checks. Unknown/malformed routes and locked puzzles resolve to `#/`; missing sandboxes resolve to their briefing; missing or wrongly owned solutions resolve to the unlocked puzzle's briefing. Empty/noncanonical fragments are replaced, not added to history. Pathname routing is not supported, and static hosts need no SPA fallback.

Persist the active dirty workshop before every transition; `pagehide` is the final boundary. Creation, duplication, deletion, completed edit gestures, imports, property changes, case changes, and clearing persist immediately. Sandbox snapshots contain the complete authoring workspace and selected case; solutions contain the editable baseline and optional scores. Sessions are created lazily per saved ID and reused on return; deleting a record also forgets its session.

Opening a puzzle solution, including a reused session or a duplicate, restores the first test case from its editable baseline at tick zero and unlocks editing. `PuzzleTestController.configure` uses the ordinary case-selection/reset path so the displayed world, interpolation state, and test UI agree. Prior scores remain intact until an edit or another test changes them; sandbox sessions retain their runtime state on return.

Duplicated puzzle solutions use numeric revisions along a straight chain: `Solution 1` → `Solution 1.1` → `Solution 1.2`. Copying an earlier revision with an existing continuation starts a lettered branch at that exact source: another copy of `Solution 1.1` becomes `Solution 1.1a.1`, then continues as `Solution 1.1a.2`; further branches from `Solution 1.1` use `b`, `c`, …, `z`, `aa`, etc. A branch from the root is `Solution 1a.1`. Nested forks add another branch marker, so names grow with branching depth rather than every duplication. Surviving descendants reserve deleted ancestors' names and family prefixes within the puzzle, including after reload. No separate ancestry metadata is stored; fully deleted lineages may reuse names, and existing names are not rewritten or assigned a reconstructed history.

Sandboxes use the same algorithm from `saved-design-names.ts`, with `Sandbox` in place of `Solution` and names reserved across the entire sandbox collection rather than per puzzle. For example, a straight chain is `Sandbox 1` → `Sandbox 1.1` → `Sandbox 1.2`, and another copy of `Sandbox 1.1` becomes `Sandbox 1.1a.1`. Existing saved names remain unchanged.

Puzzle briefing solution rows display newest-created first, including duplicates. Editing an existing solution does not move it; stored model order is unchanged.

Sandbox briefing rows use their panel's available width rather than the puzzle score-row breakpoint: names and actions share a row from 440 CSS pixels of panel content width, and stack below that. Puzzle rows retain room for their four scores.

A session has four related runtime references:

* `world`: current mutable simulation state.
* `simulation`: advances that world.
* `baseline`: tick-zero editable design used for reset and persistence.
* `previousWorld`: render-only interpolation state, copied before stepping and synchronized after edits/reset.

Import replacement updates them together and starts the simulation at the imported tick. Only `WorkshopSurfaceController` supplies active session references to the browser entry point. Simulation never writes into the baseline.

Accepted sandbox edits copy the current world to baseline. Puzzle edits transfer only editable cells, configurable state, and permitted welds to the canonical baseline, never the selected test case's fixed terrain. Edits reset tick/result, synchronize previous state, and mark the record dirty. Starting or stepping calls `beginSimulation` before the first tick; puzzles remain locked until reset, while sandboxes remain editable. Reset stops running, rebuilds the selected case from fixed state plus baseline, unlocks editing, and synchronizes interpolation.

`WorkshopSessionController` retains up to 30 undoable edits per session as serialized in-memory snapshots, seeded after saved/imported state is attached. Puzzle snapshots contain the canonical editable baseline; sandbox snapshots include every authored case, metadata, component prices (including disabled components), annotations, nested boards, and editable regions. Internal authoring snapshots preserve exact text ownership rather than applying puzzle-export normalization. History survives in-app navigation but not reloads; the restored design persists immediately and invalidates solution scores like an ordinary edit.

Only accepted edits advance history. No-op commits preserve redo, while a new edit after undo discards the redo branch. Simulation, testing, reset, and case browsing never append snapshots. Tile/weld gestures carry one identity across pre-tick segment commits, so a complete drag is one undo action even while a sandbox runs. Undo/redo finishes pending gestures and selection transforms, pauses playback, replaces session runtime references at tick zero, and remounts the root board; puzzle restoration rebuilds the currently viewed fixed test case. This restores committed editing states, not individual physics ticks. Puzzle history is unavailable until Reset unlocks editing.

## Workshop editing contracts

* `src/ui/motion.css` provides opacity-based button press feedback and entrance fades when screens become visible or dialogs open. Decorated menu cards and dialogs do not translate or scale, keeping thin inlays stable; navigation/dialog actions remain immediate. Global button transitions exclude backgrounds because gradient-to-solid changes cannot interpolate. These DOM effects are independent of simulation interpolation; the browser's reduced-motion preference disables them and existing palette hover lifts/saved-snippet pulses.
* `component-palette.ts` derives categories, visible-order shortcuts, and availability from tile metadata and the puzzle catalog. Sandbox palettes stay complete/unpriced even though new authored puzzle catalogs start disabled. Suggested authoring prices come from `TileDefinition.defaultPrice`; enabled saved/imported prices are explicit. Switching workshop sessions (including creating a new solution or sandbox) selects the first block in visible palette order, or the selection tool for an empty catalog, and opens the Components tab. Returning from a briefing to the same active session preserves the chosen tool; reloading initializes selection again.
* Palette groups appear as Materials, Motion, Transformation, Rune Components, Combiner Runes, Advanced Runes, and Puzzle Tools. Materials combine ordinary materials, then metals, then the five gemstones. Component order is shared by sandbox/puzzle palettes and puzzle-authoring catalogs; shortcuts follow the filtered visible order.
* Hovering a priced palette component shows its catalog price on the icon, using the same overlay as hovering the total puzzle cost (which reveals all palette prices). Leaving the icon hides its price; sandbox palettes remain unpriced.
* Puzzle price edits show a signed popup above the total, using circuit blue for increases and red for decreases. Changes accumulate while the 1.4-second hold/fade is active; net-zero changes hide it. Workshop entry resets feedback, and simulation changes do not produce price deltas.
* The palette sidebar's right-edge separator supports pointer dragging, Left/Right adjustments, Home/End limits, and double-click reset. Width is retained across in-app navigation, not reloads, and bounded to preserve board space. Narrow palettes shrink component icons and move the workshop title below its buttons.
* Palette hover uses `TileDefinition.palette.extendedDescription` paragraphs alongside the short description in a wider inspector. Every CircuitGates reference includes a signed, color-coded 3×3 truth table: input 1 is the columns, input 2 is the rows, and the third input is disconnected. Subtractor tables use rear/left inputs; selector tables use rear control/left signal, with the unused right input neutral. Board hover normally shows only the short description and live component properties; holding Alt adds the same extended reference and truth table while retaining cell identity and live properties. Pressing/releasing Alt updates a stationary hover, and window blur clears it. Tiles without palette metadata retain their short description. Tool help remains separate.
* `canvas-interaction-controller.ts`, `src/render/pointer-gesture.ts`, and `grid-drag.ts` classify gestures and provide continuous grid traversal. Cancel pending gestures on blur, capture loss, stale initiating-button masks, or session changes. Palette/snippet drag-and-drop follows the same edit and cancellation policies as board tools.
* Middle-clicking empty grid cells or the canvas surround restores the previously selected block. Q also restores the previous block when no grid cell is hovered. Middle-drag still pans without picking; nested-array virtual ports retain their special conduit-picking behavior.
* Simulation ticks retain sandbox tile-placement, erasure, and weld/unweld pointer capture, committing changed segments before stepping. Holding a gesture without further edits does not update the baseline. Selection, editable-region, and text-box gestures finish before stepping; puzzle edits still end before simulation locks editing.
* Bottom-bar **UNDO** / **REDO** use Ctrl+Z and Ctrl+Shift+Z (also Ctrl+Y), with Command equivalents. Shortcuts ignore text entry, open dialogs, IME composition, consumed events, and held-key repeats. Accepted editable-region additions/removals commit authoring history and persistence separately from live board edits.
* Ordinary placement welds consecutive eligible cells along the drag path, including crossings in either direction between editable cells and fixed puzzle tiles; fixed tiles are not replaced. Shift placement welds all eligible neighbors. Fast diagonals use an edge-connected staircase. Weld edits respect tile eligibility and editable perimeter/internal edges. Temporary Control welding restores the previous tool on release/blur and must not interfere with clipboard selection shortcuts.
* Explicit weld/unweld clicks, hover highlights, and drags target a square centered on each internal edge, extending 0.2 cells in each direction. Tile centers and four-tile corners are dead zones. Continuous drags visit every target intersected between pointer events, including paths slightly off a grid line, without welding perpendicular seams at corner crossings. These targets scale with zoom; automatic placement welding is unchanged.
* Rejected board edits give transient feedback without changing the world or playing edit sounds: simulation-locked puzzle attempts flash Reset; tile edits and explicit weld/unweld attempts outside the editable region flash its border red; in-region weld attempts on occupied but ineligible neighbors tint both adjacent cells red. Weld/unweld attempts with either neighbor empty are silent no-ops, even outside the editable region. Placement feedback also covers palette drops. Automatic neighbor welding still silently skips ineligible neighbors. Fixed nested views with no editable boundary flash the board frame instead.
* `src/game/tile-selection.ts` owns rectangular capture, floating overlap-safe moves, clipboard, rotation/reflection, deletion, configuration/weld preservation, and destination validation. Puzzle selections intersect editable regions. Invalid destinations cancel rather than modify fixed cells. Enter commits/deselects before any array navigation; V toggles selection versus the remembered tool.
* Selection-tool right-clicks and right-drags erase tiles through the ordinary tile-edit gesture without changing the selected tool. Any floating selection is committed/deselected before erasure so stale selection contents cannot restore deleted tiles. Edit locks, editable-region restrictions, persistence, and sandbox-running gesture handling match ordinary tile erasure; Alt-right-drag still pans.
* Reflection preserves component handedness as well as facing, including in captured snippets and nested arrays. M toggles placement handedness for mirrorable components, swapping local left/right without changing facing and immediately updating the cursor/board preview; held-key repeats are ignored. Q picking retains the component's facing and handedness for subsequent placement and rotation; selecting from the palette starts unmirrored. Scene saves, editable-design transfer, offset crops, and independent test-case overrides preserve handedness.
* Selection toolbar **COPY CONFIG** captures E-dialog settings from a selection containing exactly one configurable component; non-configurable tiles may also be selected. **PASTE CONFIG** commits the destination selection, applies settings only to matching tile kinds, deselects, and persists. The clipboard is separate from tile/snippet copying, survives in-app navigation, and clears on reload. Paste respects edit locks and editable regions; orientations and welds are unchanged except for any pending selection transform. Live buffers/cursors/counts and trace order are not copied. Rune arrays copy dimensions/description, not inner contents; resizing keeps destination contents centered and may crop them, as in the E dialog.
* Root sandbox selections offer a confirmed crop action. It commits floating selection edits, stops simulation, crops every authored test case to the displayed selection rectangle, translates annotation centers and clips editable regions, refits the camera, and persists immediately. Annotations whose centers leave the board are dropped. Internal welds and component state survive; perimeter welds are removed. Puzzle boards and nested-array views do not offer cropping.
* Root sandboxes offer compact −/+ buttons outside each board edge. Each click removes/adds one row or column across every authored test case; top/left operations translate retained tiles, welds, component state, nested boards, annotation centers, and editable regions together. Removals require confirmation and drop out-of-bounds annotation centers while clipping cropped contents/regions. Resizing commits selections, stops simulation, resets to tick zero, refits the camera, and persists immediately. Dimension-limit buttons are disabled; puzzle and nested views hide the controls.
* `component-configuration-dialog.ts` owns numeric, name, ternary-grid, and array configuration. Save and Escape share validation; invalid drafts stay open, Cancel discards, and IME composition does not submit. E can inspect fixed components read-only while puzzle editing is unlocked; simulation-locked puzzle configuration is unavailable. Ternary painting uses pointer capture and the normal cancellation rules.
* Resizing lore-rune and sequence-checker grids preserves the top-left overlapping rectangle. Added right-hand columns and bottom rows contain zero; shrinking discards cropped cells. Invalid dimension inputs leave the last valid draft intact until both dimensions are valid again.
* Lore-rune and sequence-checker editors reserve a centered 9×9-sized grid area so dimension changes do not move the resize controls. Narrow dialogs shrink the grid's width and scroll their inner content vertically; the fixed 3×3 lookup editor keeps its compact labeled layout.
* Discard runes use the numeric E dialog for the initial tick count (0–99). Their inspector shows suppressed ticks versus N and marks completed windows as pass-through. Copy/paste configuration transfers N only, using the same changed-value reset and unchanged-value no-op rules as other numeric components.
* Beam Block/Body Sensors use the E dialog for a threshold (0–120000, default 0) and “Match all nonempty blocks / bodies” (default off). Output is −1 below the threshold, 0 at it, and +1 above it; match-all bypasses the rear template. Save/Escape validation, Cancel, read-only inspection, and copy/paste configuration follow the ordinary component workflow. The inspector shows threshold and matching mode.
* Sequence checker configuration includes “Ignore zero inputs”, off by default. Enabling it requires every expected grid cell to be +1 or -1; invalid drafts cannot save, including through Escape. The option is disabled when viewing fixed components read-only.
* Lore rune configuration includes independent “Wrap horizontally” and “Wrap vertically” checkboxes, both on by default. Disabled edges reject cursor moves, including carries from the other axis. Save/Escape, Cancel, read-only inspection, and copy/paste configuration use the ordinary grid workflow; copying configuration transfers wrapping settings but not the live cursor.
* Lookup runes reuse the ternary-grid E dialog with dimensions locked to 3×3. Column headers identify local-left input and row headers rear input, ordered -1, 0, +1; each cell's accessible label includes both inputs and its output. Painting, fill, Save/Escape, read-only inspection, and copy/paste configuration use the ordinary grid workflow.
* `src/game/snippet-library.ts`, its controller, and `snippet-panel.ts` persist reusable fragments independently of puzzles. Snippets are cropped tick-zero boards retaining configuration, orientation, and welds, not live charges. Placement uses floating selections; unavailable puzzle components are removed, and wholly unavailable snippets are disabled.
* `src/simulation/text-box.ts` owns immutable annotations; `text-box-tool.ts` owns editing. Text is independent of tiles, physics, prices, and footprint. Authored puzzle text is read-only to solvers; player text persists across case views and may lie outside tile-editable regions. Fixed nested arrays and simulation locks reject edits. Annotations store only their center, text, ID, and owner; Canvas-derived bounds are shared by drawing and hit testing. Creating a note centers it on the click; editing preserves its center unless fitting requires moving it inside the board. Transforms keep text upright; resizing translates centers and drops annotations outside the board.

Keep keyboard shortcuts isolated from text entry, modal editing, IME composition, inappropriate modifiers, and held-key repeats. Transport shortcuts respect availability. Menus retain keyboard navigation and Escape/focus-leave/outside-click dismissal. Inspect current event wiring and `e2e/` for exact bindings rather than duplicating shortcut logic.

Escape returns from a puzzle briefing to the main menu and opens Settings from the main menu. In puzzle workshops, Escape invokes the same reset action as R or the Reset button, including from nested-array views; use the nested Back button to leave an array without resetting. Sandbox Escape still leaves nested arrays without resetting simulation. Open dialogs retain Escape dismissal without resetting, triggering navigation, or opening another dialog. These Escape shortcuts ignore text entry, IME composition, modifiers, consumed events, and held-key repeats in puzzle workshops, briefings, and the main menu.

F1 opens About from the main menu and the existing information dialog from a workshop (puzzle information for solutions, puzzle properties for sandboxes). It uses the same text-entry, composition, modifier, consumed-event, repeat, and modal guards. Open dialogs block underlying workshop keyboard edits.

## Nested views and signal traces

`WorkshopSurfaceController` tracks array tile-ID paths from the root, following moved arrays and surviving resets. Enter/leave reuses the main canvas, palette, tools, inspector, and configuration UI. Editable arrays allow all inner cells; fixed arrays allow none. A breadcrumb climbs outward; the renderer receives the containing array's side charges for virtual ports.

Entering an array saves its parent's camera and fits the inner board. Leaving restores that parent's zoom and grid-space center, independently at every nesting depth. If an entered array disappears, path repair restores the surviving ancestor's camera. Runtime remounts that return to the root without requesting a fit restore the root camera, never the inner board's camera; session mounts clear the saved stack.

The session world, simulation, baseline, and previous world stay root-level even while a nested world is displayed. Steps, exports, puzzle scores, and signal traces use the root. Do not accidentally persist a displayed inner board as the session root.

`src/game/signal-traces.ts` records every monitor in the root and recursively nested arrays once per committed tick, keyed by its containing array-ID path plus stable tile ID. Histories follow moved arrays without colliding with equal IDs in other boards. Every step path, including fast-forward via `afterStep`, must notify it; missing ticks throw. History restarts on world replacement, backward ticks, or tick-zero edits, including inner-board-only edits. `signal-panel.ts` displays monitor history and complete ROM/checker contents grouped by category in first-appearance order, sorting each category by saved order with depth-first row-major ties; nested labels identify the array-ID path, with full labels available on hover. Hover highlights the source component when its owning board is displayed, or its containing rune array on the displayed ancestor board. Sources outside the displayed subtree remain unhighlighted. The recorder refreshes board ancestry alongside its revision snapshots, preserving stable-ID highlights through movement and dropping detached boards. Ordinary checker alignment uses the first active input tick, not latency assumed from tick zero. Ignore-zero checkers instead show sequence positions starting at row zero, with a “(pulses)” label: unknown gaps cannot be mapped to future ticks. Trace history and checker start ticks are display-only.

Automatic trace labels distinguish monitors (`MONITOR`) from lore graphers (`LORE`); nested labels prefix the containing array-ID path with `#`. Panel headers ellipsize overlong labels instead of compressing the glyphs, and hover titles retain the full configured or automatic label.

Monitor and lore grapher configuration includes a category (blank by default, at most 12 characters, trimmed on submission). Matching category strings group traces across nested boards. Named groups display headings above their traces; the blank category has no heading. The extra heading row is absent when all categories are blank. Full category names remain available on hover when headings ellipsize. Categories follow component state through edits, transforms, cloning, reset, snippets, and scene/puzzle persistence; JSON omits blank categories and imports omitted categories as blank.

Drag a trace header horizontally to reorder its category, with a highlighted live preview. Drops outside the category and cancelled gestures discard the preview. Reordering follows the puzzle simulation edit lock: reset before arranging traces. The hidden integer `order` lives on monitors/graphers, survives component copying and scene/puzzle persistence, and is never shown in the configuration dialog; JSON omits zero and imports omitted order as zero. Fixed puzzle machinery also accepts display-only ordering, including inside fixed arrays: case/baseline transfer copies order between matching components without altering their labels, categories, circuit configuration, or terrain.

## Puzzles, authoring, and completion

* `puzzles.ts` loads shipped JSON from `src/game/puzzles/` through `puzzle-format.ts`. Registry order follows `puzzle-groups.ts`, then numeric puzzle order and ID. Groups unlock by gemstones; completions reveal further puzzles within a group.
* Mechanical puzzles use Transport, Extraction, Manufacturing, and Mining groups; unlock thresholds and initial availability live in `puzzle-groups.ts`. Empty groups remain available in authoring but are hidden from the puzzle map. Puzzle IDs, saved solutions, and completion records are independent of category assignments.
* Puzzle `difficulty` is `"tutorial"` or an integer from 1–5 (Easy, Intermediate, Difficult, Expert, Masterwork); omission and new sandboxes default to 1. Shipped puzzles specify it explicitly. Puzzle properties edit the rating, and puzzle export/import and saved-sandbox snapshots preserve it. Main-menu cards show a graduation cap for tutorials or the corresponding number of stars; the puzzle briefing also shows the difficulty name. Both provide explanatory hover text and accessible labels, including the numeric rating out of five for starred puzzles, independent of completion/unlock state.
* Every puzzle has a validated priced component catalog, editable regions, explicit board dimensions, at least one victory block in every resolved case, and an implicit `standard` case. Additional named stable-ID cases apply sparse board-field overrides and must match base dimensions. Cycle limits default to 1,000 and cannot exceed 10,000.
* Briefings warn when a puzzle has multiple test cases, including the standard case in the displayed count. Puzzle workshops hide the CASE selector for single-case puzzles; multi-case puzzles retain selection, and sandboxes always retain the menu for case authoring.
* `sandbox-puzzle-authoring.ts` owns scene/puzzle import, metadata, independent case boards, case duplication/deletion, selected case, and board resizing/cropping. Properties resize from the top-left; edge controls support padding/cropping any side; selection cropping translates a chosen rectangle to the new origin across all cases. `puzzle-export.ts` serializes authored puzzles. Scene import and new sandbox catalogs start disabled; saved/imported enabled prices remain explicit. Puzzle imports restore metadata, catalog, regions, and all cases, not just tiles.
* Authored additional-case exports contain only board fields that differ from the standard case; identical cases use empty overrides. Comparison is field-level, including complete nested component state. Empty arrays remain explicit when needed to clear inherited state, and each case retains its own identity and cycle-limit override.
* `editable-solution.ts` transfers the shared editable design into each isolated fixed-case world. Catalog restrictions are enforced at placement as well as palette/shortcut selection. Puzzle clearing/import paths must preserve fixed terrain.
* Pre-placed components inside editable regions are starter suggestions, not fixed machinery: they count at full catalog price and may be removed or overwritten. New solutions inherit the standard board's suggestions; the saved editable baseline, including empty cells and removed perimeter welds, replaces those regions in every test case. Reset and reload retain the player's edited design, not the original suggestions.
* A complete visible or fast-forwarded test runs every case. First loss or cycle limit stops on that terminal board and clears prior solution confirmation without opening the success report. Only all-case success atomically persists baseline and price, mean-cycle, footprint, and combined scores, and records completion. Cycles are the unrounded arithmetic mean across all cases; combined is price + mean cycles + footprint. Reports retain individual case tick counts. Manual steps never update progress.
* Test/Space toggles automatic verification and paused manual mode without replacing the run, including between cases. Paused tests retain editing/case-selection locks and allow Step/N, Resume, or Fast/F. Resuming restarts the speed ramp and discards elapsed paused time; between-case resume waits the normal transition delay.
* Visible verification starts each case or resume at the speed-menu selection and doubles that rate every 6 seconds, stopping after two doublings (4× the selection after 12 seconds). The effective rate also cannot exceed 60 ticks/second. Selection changes apply during a run; the default 5 ramps to 10 after 6 seconds and stays at 20 from 12 seconds onward. The first frame after starting/resuming excludes pre-start time. Sandbox speed remains constant, and Fast verification bypasses this ramp and its caps.
* Fast verification advances on animation frames, with at most 100 ticks or 8 ms of simulation/trace work per frame (a single tick is indivisible). It renders committed state without interpolation, records every tick's signals, and yields at case boundaries before mounting the next case. Pause, reset, and navigation can interrupt between batches; only terminal all-case success records completion. Headless `runPuzzleTests` remains synchronous.
* Newly recorded progress immediately updates gemstones, unlocks, and route access without replacing the workshop. Success reports offer the immediate next puzzle only if now unlocked; navigation uses the ordinary persistence boundary.
* Success reports compare each score against the minimum of that metric across previously confirmed saved solutions for the same puzzle, including the active solution's prior result. Capture these values before recording replaces that result; first completions show no deltas. Negative deltas indicate improvement because all four metrics are minimized.
* Briefings show each metric's minimum across currently confirmed saved solutions, with a community histogram, personal-best marker, and percentile-mineral rank. Success reports rank and mark the actual current run; with two or more saved solutions they also show each metric's current saved best after recording the run. Best and current markers remain distinct when equal. These saved bests can differ from the pre-run deltas and from the server's best-ever submissions after edits/deletions. Combined remains the best actual combined score, not the sum of independent minima.
* `CommunityScoresView` owns network status and refreshes shared DOM/CSS charts from `score-histograms.ts`. Charts retain local summaries when the API is disabled or unavailable, and show no ranks for empty cohorts. Metric titles and local-best values share a header; the best value's tooltip includes the global best instead of adding a separate record line. Bar inspection supports hover, tap/click, focus, arrow keys, Home, and End; each chart has one tab stop. Pointer-only inspection clears on leave, restoring a focused bucket when present; click/tap focuses a bucket and blur clears it unless another bucket is hovered. Layouts adapt from four to two to one column. Success reports scroll within the viewport and use compact spacing with 60px plots, versus 100px briefing plots. Percentile thresholds, tie handling, and cohort semantics are documented in [community backend](community-backend.md#browser-integration).
* Briefing network status lives beside the histogram heading: “Community scores —” followed by player count, loading, unavailable, or not configured. The same status node survives chart refreshes; success reports retain their separate submission status.
* Briefing solution rows and shared histogram score values color each metric independently by its community mineral rank: iron is silver, gold is gold, and mithril is blue, with theme-specific shades. Coal and unranked values retain their original colors. Solution rows reuse the briefing histogram response (no extra requests), expose ranks on hover, and remain neutral while loading or when the cohort is empty/unavailable. Histogram marker shapes/colors still distinguish local best from the current run.
* Briefing solution rows are highlighted when they tie for the lowest price, average cycles, footprint, or actual combined score among confirmed saved solutions. Each independently best value is underlined; comparisons use full stored precision, not rounded display values. Unconfirmed solutions never qualify, and community mineral colors remain independent of these personal-best markings.
* Completed main-menu puzzle cards show the mineral rank of the best currently confirmed combined score: mithril blue, gold, iron silver, or muted coal, with a tinted background and border. The grade label supplements color; hover text identifies the metric, percentile, provisional status, and cached-cohort policy. Menu visits and reloads issue no community requests: they reuse locally cached histograms refreshed by briefings and success reports. Missing/invalid/empty caches or absent confirmed scores retain ordinary completion styling; editing/deleting solutions recomputes the grade on the next menu visit.
* Score displays and histogram bounds use at most two decimal places; rounded bounds carry an approximation sign. Persistence, bucket membership, best-score comparisons, and percentile ranks retain full precision. Saved solutions carry a separate scoring version; missing or mismatched versions discard their scores/confirmation without discarding designs or puzzle progression. Previously summed-cycle scores therefore require a fresh successful test.
* Puzzle-workshop download/open-in-sandbox actions use the original complete shipped puzzle, not the running state or player's design. Opening creates an independently saved sandbox. Sandbox export uses authored metadata/cases.
* Scene and image downloads in puzzle workshops use `<puzzle-id>.json` and `<puzzle-id>.png`. Sandbox downloads retain `factory2d-scene.json` and `factory2d-grid.png`. Image filenames capture the active puzzle before asynchronous PNG encoding.
* Scene/puzzle file import is sandbox-only. Puzzle workshops hide the Import control rather than reserving space for a disabled button; entering a sandbox restores it. Puzzle scene importing is unsupported.

`puzzle-scores.ts`, `puzzle-progress.ts`, and `puzzle-components.ts` centralize scoring, progression storage, and catalog validation. `src/ui/main-menu.ts`, `puzzle-info.ts`, `sandbox-info.ts`, `workshop-info-dialog.ts`, and `puzzle-test-report.ts` present these models. Keep validation and lifecycle policy out of presentation code.

## Storage and verification

Scene and puzzle JSON are deterministic/versioned and fully validated before replacing live state; see the simulation reference for nested-board fields and fresh runtime IDs. `player-data.ts` exports all localStorage entries deterministically and imports an exact replacement with rollback on failure. `installation-id.ts` establishes `factory2d.installation-id` with `crypto.randomUUID()` at startup (and before export). Clear preserves that UUID; full imports transfer the exported UUID, while older files without it retain the destination UUID. Invalid stored/imported identities fail without silently rotating them. Successful import/clear reloads the app; destructive actions require confirmation. Clearing local data does not delete server scores or published puzzles.

Settings includes a persisted Light Mode toggle, defaulting to dark. A sun/moon button at the bottom-left of puzzle and sandbox workshops shares the same setting, with its icon and accessible label describing the next action. `src/ui/theme.ts` synchronizes both controls, applies `data-theme` on the document root, and stores `factory2d.theme`; the existing player-data export/import/clear includes this preference. `src/styles.css` owns both UI palettes and native-control color schemes. The active theme also controls the canvas surround, board background, grid lines, and outer board border; tile artwork and circuit signal colors remain unchanged.

Workshop Settings and mute shortcuts sit beside the theme button. Settings opens the same modal as the main menu; the one-character mute button shares Sound Effects persistence and updates immediately when either control changes. Its pressed state means muted, opposite to the Sound Effects toggle.

Interface monospace labels use bundled Noto Sans Mono variable weights rather than platform-specific fonts. The Latin WOFF2 asset lives in `src/assets/`; its SIL Open Font License ships in `public/fonts/OFL.txt`. No runtime font service is required. Puzzle groups use auto-fill grid tracks so sparse groups retain the same card widths as populated groups, with single-column reflow on narrow screens; status marks and labels remain on one line.

Settings also includes Tile Bevels, enabled by default and persisted as `factory2d.bevels`. `src/ui/bevel-setting.ts` updates the shared rendering preference and refreshes previews after a successful save. This preference participates in the existing player-data export/import/clear behavior.

Settings includes Animations, enabled by default and persisted as `factory2d.animations`, synchronized with the workshop ANIMATE checkbox by `src/ui/animation-settings.ts`. Its adjacent Animate While Paused preference is off by default and persisted as `factory2d.animate-while-paused`; it is disabled/greyed out while global animations are off, without losing its saved value. Paused looping machinery requires both toggles, while enabled finite single-step effects may finish. Both settings save before applying, restore controls on save failure, and participate in player-data export/import/clear.

Settings includes an “Unlock All Puzzles” cheat toggle, off by default and persisted as `factory2d.unlock-all-puzzles`. `NavigationController` applies it to the puzzle map, direct/history route access, and next-puzzle navigation. It bypasses both group and within-group progression without recording completions, awarding gemstones, or changing solution scores; turning it off restores normal progression. Saving must succeed before access or the button's pressed state changes. Player-data export/import/clear includes the toggle.

Settings includes Sound Effects, enabled by default and persisted as `factory2d.sounds`, including in player-data export/import/clear. `src/ui/workshop-sounds.ts` lazily unlocks Web Audio on pointer/keyboard interaction and synthesizes short placement/removal and weld/unweld tones for accepted board-tool edits, plus selection placement/deletion feedback. Rapid edit feedback is rate-limited; rejected/no-op edits are silent. A three-note chime accompanies victory in sandbox play/stepping. Puzzle verification plays it once when the all-tests-passed report opens, never for individual cases, in visible, fast, and manually stepped runs. Muting silences even scheduled tones. Audio is browser-only, skips hidden pages, and never changes simulation state.

Settings provides Master volume and Bell volume sliders (0–100%, default 100%), saved as `factory2d.master-volume` and `factory2d.bell-volume`. Positive values use a logarithmic gain curve, `10 ** ((percent - 100) / 50)` (50% is −20 dB); zero is silent. Bell gain multiplies master gain through a separate Web Audio bus, leaving edit and result sounds unaffected by the bell slider. Changes apply immediately to ringing/scheduled sounds and persist before taking effect; failed saves restore the control. Sound Effects and the workshop mute shortcut silence the master output without changing either level. Player-data export/import/clear includes both preferences.

`src/ui/spatial-sound.ts` positions edit, bell, and machinery feedback relative to the displayed camera, sampled at sound onset. Horizontal displacement in canvas half-widths drives clamped stereo pan; attenuation is `min(1, cellSize / 32) / (1 + dx² + dy²)`, with displacement normalized by each canvas half-dimension in CSS pixels. Zooming out quiets sources; distant/offscreen sources fade rather than abruptly cutting out. Nested sources use their outermost containing array's cell in the displayed board; ancestors and sibling subtrees are inaudible while inside an array. Observers preserve every source, then playback coalesces each pitch/voice at its loudest site (first observed site breaks ties), keeping dense machines bounded. Bell partials and multi-part machinery voices share a gain/panner bus, disconnected after their last source ends. Master/Bell volume and mute remain downstream; victory/loss chimes stay centered and unattenuated.

Machinery feedback uses `src/ui/machinery-observer.ts` at the same manual-step and below-15-ticks/second boundaries as bells, including nested boards. Surviving pistons sound only on successful extension/retraction, following the arm's stable ID through base replacement; held charge, blocked strokes, and passive movement are silent. Surviving drills, grinders, and furnaces sound on active rear-output ticks, including completion, but not while paused, jammed, or idle. Newly produced/copied machines do not inherit an observed sound. Each voice coalesces once per tick within the displayed subtree. `WorkshopSounds.playMachinery` synthesizes short filtered-noise bursts and mechanical tones through the master bus, independent of Bell volume and body size. Mute, hidden-page, and fast-playback suppression follow ordinary audio policy; sounds never enter simulation state or trigger bell/resonator behavior.

Welders, splitters, laser splitters, and dismantlers have distinct voices on successful rear-change pulses only; unchanged, disabled, protected, or conflicting weld operations stay silent. Duplicators sound on committed body copies, and assemblers on both recipe consumption and product emission, never blocked attempts. `src/simulation/machinery-activity.ts` retains sparse per-world event arrays outside simulation state, cleared before each observed tick and closed on collection; resolvers report every actual commit's voice and cell, not interpolation copies. This catches products that move away during the same tick and assembler consumption without a circuit pulse. Nested-world copies and skipped observation windows cannot replay or accumulate old activity.

Committed destruction shares this activity path: drilled ordinary blocks crunch, fragile blocks shatter, and fasteners snap, including when a drill destroys glass or a fastener. `recordShatterEffects` reports sound independently of mounted shatter animations, so nested boards and disabled animations still sound. Each breakage voice coalesces once per observed tick through the machinery master bus, independent of Bell volume. Ordinary erasing, machine consumption, blocked motion, and nonfatal glass landings are silent; paused or skipped observation windows never replay breakage.

Bell feedback uses `src/ui/bell-observer.ts` to capture sparse stable-ID positions immediately before manual steps and automatic ticks below 15 ticks/second, consuming net horizontal movement afterward, recursively within nested boards. `main.ts` owns the observer independently of audio availability; each moved bell emits a visual ring, then `WorkshopSounds.playBells` spatializes/coalesces pitches and applies mute/volume/hidden-page rules. Final body sizes 1–37 map to 37 equal-tempered semitone pitches descending across three octaves from F5 (698.46 Hz) to F2 (87.31 Hz), tuned to A4 = 440 Hz. Sizes 13 and 25 give F4 and F3, and larger bodies clamp to the size-37 pitch. Shared `BELL_STEPS_PER_OCTAVE` and `BELL_PITCH_COUNT` constants keep observation and playback aligned. The observer collects pitch/world/cell events in a reusable array, consumed before the next collection, with no 32-bit pitch limit. `workshop-sounds.ts` blends timbre by octave depth, preserving the short highest bell and the deep-bell voice at F2. Across the first octave, the base voice adds a split minor-third tierce, strengthens the nominal, and lengthens partial decays. Starting 5/7 of an octave below F5, the mix progressively blends toward the deep voice: the hum and prime fade sooner, the hum is quieter, upper ringing modes are stronger and longer-lived, and two brief high modes add a metallic strike. This shifts energy into more audible frequencies rather than boosting the bass uniformly. The lowest hum partial remains approximately 44 Hz; pitch spacing is independent of the timbre blend. Equal pitches share a voice per tick. Audio rings even with animation disabled; faster playback and fast verification are silent. `PuzzleTestController.beforeStep` runs on every tick with the actual rate (zero for manual steps, infinity for fast verification) and an interpolation flag, so bell observation does not require copying render snapshots.

`BellObserver` also wraps the shared simulation `TonalObserver` for mallets in each local board. Strikes use the struck body's final size and cell for pitch, spatial audio, and rings; bells retain their own-body pitch and horizontal-motion rule. `TileDefinition.strikeTimbre` selects the contacted tile's voice, even for mixed-material bodies: stone, dirt, sand, ores, and floatstone use short lithophone tones; wood and mallets use dry wooden knocks; glass and gemstones use sustained chimes. Metals, bells, and unspecified machinery retain the existing metallic bell voice. Observer voice keys pack `timbre * BELL_PITCH_COUNT + pitch`, so playback coalesces only equal material/pitch pairs, not different materials at the same pitch. All voices share the Bell volume bus and manual-step/below-15-ticks-per-second observation limits. Resonator hearing remains pitch-only and independent of browser limits or timbre.

Hovering a bell or resonator shows its note name and octave (using sharps, e.g. D♯5) and current body block count in the tile inspector, including in the Alt-expanded reference. The inspector lazily retains a `WeldedBodyIndex` for its displayed world and refreshes after world changes. `src/simulation/bell-pitch.ts` owns `bellPitchForBodySize`, `BELL_STEPS_PER_OCTAVE`, and `BELL_PITCH_COUNT`, shared by resonator simulation and browser feedback; `bellNoteForPitch` and `bellFrequencyForPitch` remain in `bell-observer.ts`. Muting audio or skipping browser audio/ring observation at high speeds never disables resonator signaling.

`src/dev/diagnostic-snapshot.ts` exposes a development-only read-only snapshot of routes, tool/hover state, simulation, revisions, serialized boards, and nested view depth/dimensions. Use it with browser automation; Vite removes it from production.

Focused model/controller tests live in `tests/` alongside subsystem names. Playwright cases in `e2e/` exercise persisted production-format fixtures, routing, edit/cancel behavior, nested arrays, successful/failed verification, downloads, and responsive layout. For lifecycle changes, check navigation away/back and reload as well as the immediate on-screen result.

`npm run benchmark` uses a separate Playwright configuration to build and exercise the production workshop, importing deterministic scenes through the normal UI. It records raw RAF cadence, long tasks, thresholded event timing, first-use action latency, and optional Chrome traces without adding production diagnostics or timing assertions to the lifecycle suite. Environment/source metadata and workload-validity checks travel with the results. See [performance work](performance-todos.md#running-the-workshop-baseline) for commands, measurement boundaries, and missing coverage.

The `geode` benchmark additionally replays a checked-in saved factory from tick zero in a separately built browser page. It times snapshots, simulation, and Canvas submission independently, compares rendered/unrendered final state and movement counts, and retains first-use versus repeated-pass samples. This page imports the real simulation/renderer but not the workshop entry point; it is built only by the benchmark configuration and never adds hooks to normal production assets.

Shipped puzzles may have optional tick-zero reference scenes in `tests/fixtures/puzzle-solutions/<puzzle-id>.json`, serialized with the browser's scene exporter. `tests/puzzle-reference-solutions.test.ts` discovers existing fixtures, requires each to identify a current shipped puzzle, imports each scene, and verifies every current test case through `runPuzzleTests`. Missing fixtures do not fail the suite. Fixed machinery comes from the current puzzle definition; only allowed solution edits transfer from the fixture. To add or update a reference, save a solved design with simulation reset using **EXPORT → DOWNLOAD SCENE FILE**, store its fixture, and run `npm test -- tests/puzzle-reference-solutions.test.ts`.
